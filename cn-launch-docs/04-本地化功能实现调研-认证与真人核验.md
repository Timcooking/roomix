## 1. 设想 A：室友匹配可按性别偏好筛选（同性 / 异性 / 默认随机）

### 1.1 现状缺口
全球版 `Person` 类型**没有 gender 字段**（[src/data/people.ts:7-22](file:///d:/Agent/Roommix/src/data/people.ts#L7-L22)），10 道题里也没有性别维度，匹配算法 `compatibility()` 只吃这 10 个答案。所以这不是"改文案"，而是**新增一条与既有维度并列的、但性质完全不同的字段**：性别不是"生活习惯"，而是敏感个人信息 + 安全诉求。

### 1.2 业界怎么做
- **SpareRoom（英国，最成熟的范式）**：规则是"房东/室友**可以有偏好，但措辞必须正向**"。`"Female preferred as other housemates are female"` 允许；`"No men allowed"` 不允许，违规广告直接下架。其歧视指南同时援引 Equality Act 2010 与 Renters' Rights Act 2025 对 sex/gender、gender reassignment 的保护（[SpareRoom discrimination guide](https://www.spareroom.com/content/default/discrimination/)）。
  - 副作用也要看到：female-only 房源多到让男性用户集体抱怨（[Reddit r/HousingUK](https://www.reddit.com/r/HousingUK/comments/11r6yf8/every_other_rental_on_spareroom_is_female_only_or/)）——**"优先"和"排除"的边界是社区矛盾的雷区**。
- **中国大陆**：租房场景"限制性别：女"是既有的普遍筛选项（[知乎讨论：很多找租客的房间会限制性别女](https://www.zhihu.com/question/286796682)）；部分合租 App 已把性别作为室友匹配标签之一（[菠萝租房说明](https://m.itmop.com/downinfo/73240.html)）。
- **法律口径（事实）**：性别属《个人信息保护法》第 28 条"敏感个人信息"中"特定身份"的解释空间，处理须"特定目的 + 充分必要 + 严格保护措施"并**单独同意**（第 29 条）、告知必要性与影响（第 30 条）（[PIPL 全文](https://www.cac.gov.cn/2021-08/20/c_1631050028355286.htm)）；分级参考 [GB/T 35273-2020](https://openstd.samr.gov.cn/bzgk/std/newGbInfo?hcno=4568F276E0F8346EB0FBA097AA0CE05E)。居住场景的歧视成文法依据主要落在《妇女权益保障法》（2022 修订）（[全文](https://policy.mofcom.gov.cn/claw/clawContent.shtml?id=97046)）；招聘环节性别歧视已有"最高罚 5 万"的专门通知（[九部门通知](https://www.chinalawtranslate.com/notice-on-further-regulating-recruitment-to-promote-equal-employment-of-women/)）——**推断：居住场景暂无对应罚则，所以风险来自舆情与平台责任，而非罚款**。

### 1.3 我们的设计（推断）
1. **命名对齐 SpareRoom 话术，禁止排除式表达**：`不限（默认） / 只看同性 / 优先女生 / 优先男生`，绝不用"拒绝男性""男性勿进"。
2. **偏好只作排序信号与软提示，不作硬屏蔽**：不满足偏好的候选人仍可见，只是排序靠后 + 卡片上提示"对方希望与女生合租"。这样既满足安全诉求，又规避"拒不提供服务"争议。
3. **性别由用户自填，不从身份证 OCR 回填**——否则等于"未经单独同意即处理敏感个人信息"。身份证只用于年龄与实名一致性。
4. **性别认同独立字段**（"我使用的称谓 / 我的居住性别"），不与出生性别混用，也不并进同一列。
5. **数据模型改动**：`Person.gender`、`Person.genderPref`（`any | same | m | f`）、`State.answers.genderPref`；`compatibility()` 新增一项**但不计入 52–98 分的习惯契合度**，而是单独一条"偏好相符"标识——理由：把性别写进"合拍分"会被读成歧视性打分（推断）。
6. **女性侧安全能力优先于筛选功能**（推断，但每条都有法规映射）：默认位置只到行政区、聊天内诈骗/索要隐私话术提示、线下看房"结伴/白天/公共场所"引导、举报 → 临时限制闭环。最后一条是《网络信息内容生态治理规定》平台主体责任的低成本实现（[规定全文](https://www.cac.gov.cn/2019-12/20/c_1578375159509309.htm)）。

## 2. 设想 B：工作认证 + 学历认证 + 认证徽章

### 2.1 学历认证（学信网 CHSI）——只能"用户自证 + 平台核验"

**事实链路**：本人登录"学信档案"可申请三份官方电子报告——《教育部学籍在线验证报告》（在校生）、《教育部学历证书电子注册备案表》、《学位在线验证报告》（[申请指引](https://www.chsi.com.cn/wap/report/help/rhsq.jsp)）；2019-03-15 起在线验证码升级为 **16 位**，2025-03-27 启用新版报告（[验证查询页](https://www.chsi.com.cn/wap/report/search.jsp)）；初次申请的中文版**验证有效期最长 180 天**，到期前 1 个月可延长（[真伪验证](https://www.chsi.com.cn/wap/report/help/yzzw.jsp)、[延长有效期](https://www.chsi.com.cn/wap/report/help/rhyq.jsp)）；教育部政务服务平台同样可查（[zwfw.moe.gov.cn](https://zwfw.moe.gov.cn/)）。

**风险项（事实）**：阿里云云市场确有第三方"学历查询接口"（姓名 + 身份证号 + 证书编号），属**非官方授权数据源**（[云市场商品页](http://market.aliyun.com/products/57126001/cmapi00071317.html)）；而学信网 2025-04 声明点名了违规代办/伪授权（[声明](https://www.chsi.com.cn/xlrz/202504/20250418/2293374023.html)）。企业批量核查请走背调公司（如[猎查查](https://www.liechacha.com/)），且背调**必须本人授权**（[授权要点](https://www.51shebao.com/article/detail/6992)）。

**推断的产品方案（T1，上线后 3 个月内）**
```
用户 → 自行在学信网申请在线验证报告 → 把 16 位验证码/报告 PDF 交给 Roomix
     → Roomix 在官方验证页核验（半自动：验证码进表单，结果页截图存档）
     → 通过 → 打「学历已核验」徽章；仅存"核验通过"布尔 + 学校名 + 层次，不存报告原件
     → 到期提示：180 天有效期，续期需重新提交
```
- 成本 ≈ 0（无 API 费），审核时长 1–2 天可做到人工抽审 + 自动核验结合。
- **关键设计**：徽章只证明"学历真实"，粒度可选（学校名公开 / 仅公开"在读大学生"）。学生是本产品的高价值低频用户群（预算低、供给多），这条性价比极高。

### 2.2 工作认证——三层组合，别指望企业免登

**事实参照**：
- LinkedIn 用**工作邮箱**做"工作场所验证"，徽章分身份/雇主/学校三类，且**只有加入验证计划的 4000+ 企业邮箱可用**（[领英帮助中心](https://www.linkedin.com/help/linkedin/answer/a570556?lang=zh-CN)、[档案验证信息](https://www.linkedin.com/help/lms/answer/a1359065?lang=zh-CN)）。
- 脉脉以"实名/职业认证"为核心（[官网](https://maimai.cn/)）；其文章亦指出**企业邮箱验证并非所有员工的通用福利**（[脉脉文章](https://maimai.cn/article/detail?fid=1866998198)）——即"有企业邮箱"不等于"人人能拿"。
- BOSS 直聘的企业侧认证包含营业执照、对公账户打款、办公环境实拍（[流程说明](https://kuku.baidu.com/landing/tscp_doc/b768ecf0a5ef11298b302fb08545da9a)；争议案例：[知乎](https://www.zhihu.com/question/551423014/answer/2663438887)）。
- 钉钉/企业微信开放平台支持**企业内部应用免登与通讯录 API**（[钉钉免登](https://open.dingtalk.com/document/app/enterprise-internal-application-logon-free)、[企业微信通讯录](https://developer.work.weixin.qq.com/document/path/90329)）。

**推断：大厂员工侧免登对我们不可复用**。钉钉/企微授权登录的前提是"该企业已开通并安装你的应用"——C 端产品不可能让腾讯/字节的 IT 给 Roomix 开权限。因此现实组合是三层：

| 层 | 做法 | 覆盖 | 成本 | 可被绕过的方式 |
| --- | --- | --- | --- | --- |
| L1 企业邮箱域名白名单 | `@tencent.com` / `@bytedance.com` 等 + 邮件验证码 | 大厂白领，自动化、秒过 | 极低（邮件服务几分/封） | 外包、离职未回收账号、邮箱别名 |
| L2 工牌 / 在职证明 OCR + 人工抽审 | 上传工牌或在职证明（可打码），机审 OCR + 人工抽检 | 无企业邮箱岗位（**地推 BD、门店、数据标注、护士、教师、个体**） | 每张几分 + 审核人力 | PS 工牌（需靠抽检 + 举报闭环） |
| L3 展示字段可编辑 | "公司名 + 园区/岗位"（如"腾讯（深圳企鹅岛）""字节跳动（地推 BD/数据标注）"）默认脱敏到城市 | 全部 | 0 | — |

- **你原设想里的"腾讯（深圳企鹅岛）""字节跳动（地推 BD/数据标注）"正好说明必须做 L2**：这两类岗位的邮箱可得性差异极大，只靠 L1 会把大量真实用户挡在外面。
- L3 是"认证后保密"的落点：**核验结果与展示内容解耦**——徽章说明"已通过职业核验"，展示文本由用户自己选粒度。

### 2.3 徽章文案与公开粒度（业界惯例）
- 探探真人认证两步（图片审核 + 人脸认证）通过后头像下出**蓝 V**（[新京报](https://m.bjnews.com.cn/detail/157408911315844.html)）；认证标识被普遍理解为**提升曝光与匹配效率**（[知乎产品分析](https://zhuanlan.zhihu.com/p/136165938)）。
- 居住类品牌的表述：Wellcee 直接把"**真实房源 + 实名认证 + 安全保障**"作为品牌主张（[品牌页](https://www.wellcee.com/cn/brand-profile)）；巴乐兔以"实拍真房源/好房东"为卖点（[App Store](https://apps.apple.com/cn/app/id968348412)）；贝壳隐私政策明确"拒绝相机权限仍可手动上传/输入身份信息"（[贝壳隐私政策](https://m.ke.com/bj/zhuanti/protocol)），租赁签约人脸识别已覆盖 77 城（[人民网财经](http://finance.people.com.cn/n1/2026/0901/c1004-40790412.html)）。
- **推断的徽章分层（4 类 2 档）**：
  - 基础档（默认露出，人人可得）：`🪪 已实名`、`📸 真人已核验`
  - 进阶档（可选露出，默认脱敏）：`🎓 学历已核验`（学校名可关）、`💼 职业已核验`（可显示到"公司名/园区/岗位/仅城市"四档）
  - 惯例 = **徽章公开、原始信息不公开**（蓝 V 不显示身份证，脉脉只显示公司名且可点开看"如何验证"）。
- **用词红线（事实 + 推断）**：法律意义上的"认证"专指认证机构的合格评定，伪造/冒用认证标志可被列入严重违法失信名单（[认证认可条例](https://xzfg.moj.gov.cn/law/download?LawID=1539&type=pdf)、[失信名单办法](https://www.chinalawtranslate.com/samr-blacklist/)）。**推断：禁用"官方认证""权威认证"，统一用"已通过 XX 核验"**，并给每枚徽章一个"核验方式说明页"。

## 3. 设想 C：真人认证 / 照片认证

### 3.1 术语先对齐（推断，但能避免选型错误）
| 术语 | 含义 | 我们要不要 |
| --- | --- | --- |
| 实名核验 | 姓名 + 身份证号二/三要素一致 | **必须**（法规底线） |
| 实人核验 | 实名 + 活体 + **与权威库人脸 1:1 比对** | 远期（成本 1–1.5 元/次 + 行业资质门槛） |
| 照片一致性核验 | 活体自拍 vs 用户主页照片 1:1 比对，**不碰权威库** | **T0 就做**（敏感信息面最小，体验最好） |

### 3.2 业界范式
- **Bumble**：随机姿势实时自拍；官方把"验证"直接列为"让别人更容易看到你"的手段（[Verifying your photos](https://support.bumble.com/hc/en-us/articles/28949738572829-Verifying-your-photos)、[Standing out on Bumble](https://support.bumble.com/hc/en-us/articles/28938370080925-Standing-out-on-Bumble)）。⚠️ 网上流传的"认证后匹配量 +93%"**只见于第三方博客**（[getmatches](https://getmatches.ai/en/blog/bumble-algorithm)），**不可引用为事实**，演示时不要用。
- **Tinder**：ID + Photo Verification（视频自拍 + 证件，先在澳新试点：[新闻稿](https://au.tinderpressroom.com/news?item=122572)、[帮助页](https://www.help.tinder.com/hc/en-us/articles/19868368795917-ID-Photo-Verification)）；2026-04 上线"proof of humanity"**虹膜扫描**徽章，**完成者得 5 次免费 Boost**（[BBC](https://www.bbc.com/news/articles/cp9vppem4evo)）——这是"**认证换流量券**"最强范本，可直接抄逻辑。
- **Hinge**：自拍验证为自愿、通过后仅给徽章（[帮助页](https://help.hinge.co/hc/en-us/articles/10303221435539-What-is-Selfie-Verification)）；其 Signals 徽章证明"**徽章可以是非身份类的行为信号**"（[Signals badge](https://hinge.co/newsroom/signals-badge)）。
- **Soul**：在隐私政策中把**国家网络身份认证 App**列为实名认证方式，且"仅获取认证结果，不收集身份信息"（[Soul 隐私政策](https://themis.soulapp.cn/m/OyraGhrcJdj-RVlMC5d06A.html)）——这个"只拿结果不拿数据"的表述方式，是我们的隐私政策的最佳模板。

### 3.3 供应商能力与合规要求
- 能力项 = 证件 OCR + 活体检测 + 人脸比对权威库（[腾讯云慧眼](https://cloud.tencent.com/product/faceid)、[阿里云实人认证](https://www.aliyun.com/product/id-verification)）；SDK 侧需按[慧眼合规使用指南](https://privacy.qq.com/document/preview/f21731b4edf74aa680b18a624a4f462e)声明采集人脸视频/照片。
- 更国家级的一层是**国家网络身份认证公共服务（网号/网证）**：2025-07-15 施行，管理办法鼓励平台**自愿**接入（[管理办法第七条](https://www.cac.gov.cn/2025-05/23/c_1749711107835487.htm)、[公安部答记者问](https://www.mps.gov.cn/n6557563/c10087572/content.html)、[App Store 页面](https://apps.apple.com/cn/app/id1588080869)）；企业接入在强实名场景**免费**（[安全运营社区 FAQ](https://www.secrss.com/articles/79057)）。
- **黑产现实（事实）**：已有"百元一套真人认证视频（含身份证 + 点头摇头）"可过部分 App 验证（[中国新闻网天津](http://www.tj.chinanews.com.cn/sh/2021-04-14/detail-ihakifwr6389245.shtml)、[新京报：100 元在探探换成明星头像](https://m.bjnews.com.cn/detail/157408911315844.html)）。**推断：所以"真人认证"必须与手机号实名、设备指纹、行为风控捆绑，单靠活体不是防骗方案，只是提高成本。**

### 3.4 人脸合规硬约束（这几条直接决定 UI 长什么样）
| 依据 | 对产品的具体功能要求 |
| --- | --- |
| 《人脸识别技术应用安全管理办法》第 6 条（2025-06-01 施行，[全文](https://www.cac.gov.cn/2025-03/21/c_1744174262156096.htm)） | 人脸须**单独同意**、非捆绑；**最小必要**（能 1:1 自拍比对就不要走权威库）；**不得只提供人脸这一种验证途径** |
| 最高法人脸司法解释（2021-08-01，[发布稿](https://www.court.gov.cn/shenpan/xiangqing/315901.html)） | "不同意就不给用"构成侵权 → 必须提供**替代验证路径**（如学信验证码 + 人工抽审、邮箱验证码） |
| 《个人信息保护法》第 28/29/30 条（[全文](https://www.cac.gov.cn/2021-08/20/c_1631050028355286.htm)） | 人脸、性别、学历、公司名**各自独立开关与单独同意弹窗**，告知"必要性 + 影响"，并做隐私摘要页 |

> **推断的界面后果**：认证中心里每一项都必须是"可跳过"的，且未认证的卡片不能显示"未通过"字样（只可显示"未认证"），也不能因为不认证就禁用基础功能（浏览/聊天可用，只是不加权）。

### 3.5 ⚠️ 一条会改变架构的硬约束：人脸信息不得经互联网外传

已核实原文（[国务院政策文件库 · 国家网信办、公安部令第 19 号](https://www.gov.cn/zhengce/zhengceku/202503/content_7016075.htm)，2025-03-13 公布、**2025-06-01 施行**；另有[网信办答记者问](https://www.cac.gov.cn/2025-03/21/c_1744259774719484.htm)）：

> 处理人脸信息须**单独同意**（第六、七条）；**除法律法规另有规定或取得单独同意外，人脸信息应存储于人脸识别设备内，不得通过互联网对外传输**；保存期限不得超过实现目的所必需的最短时限。

**【事实】这与本文第 3.1 节提出的"自拍 vs 主页照片 1:1 比对"方案存在直接冲突**：一旦自拍图上传到我们的服务器做比对，就是"人脸信息经互联网传输 + 由平台留存"，正好落在被限制的范围内。三条可选出路【推断】：

| 路线 | 做法 | 代价 |
| --- | --- | --- |
| **A. 供应商端内完成（推荐）** | 不自建比对，全部走阿里云/腾讯云实人认证的**合规 SDK 通道**，我们只收"通过/不通过 + 分数"回调，不落原始人脸数据 | 单价 0.6–1.5 元/次；需签供应商数据处理协议并在隐私政策中列明供应商；**这是唯一不需要我们自己承担"存储人脸"责任的做法** |
| **B. 端侧比对** | 主页照片下发到设备，在端侧完成自拍与主页照比对，只回传结果与随机 nonce | 需自研端侧模型与反作弊（nonce 会被重放攻击）；工程量最大，但数据面最小 |
| **C. 明示单独同意 + 最短保存** | 走云端比对，但单独同意弹窗 + 比对后立即删除原始图（只留结果与哈希）+ 提供替代验证路径 | 法条的"取得单独同意外"例外能否覆盖我们的场景**存在解释风险**；必须有律所意见，不能想当然 |

**【推断】结论**：真人核验 v1 应改为 **路线 A（供应商 SDK，只拿结果）+ 非人脸替代路径**（学信验证码、企业邮箱验证码、人工抽审），而**不是**我原先设想的自建云端 1:1 比对。Soul"仅获取认证结果，不收集身份信息"的表述（[Soul 隐私政策](https://themis.soulapp.cn/m/OyraGhrcJdj-RVlMC5d06A.html)）正是路线 A 的合规范式。

> 附带影响：《条例》第 39 条对"违规出租非居住空间"设罚款（单位 2 万–10 万、个人 2000–1 万），而**住房租赁场景的人脸/实名专项执法案例截至 2026-11 未检索到**——低执法频率不等于低义务，尤其《个人信息保护法》与"清朗"系列专项整治是通用抓手。

## 4. 设想 D：认证后增加曝光

**行业做法（事实）**：Tinder 用 5 次免费 Boost 换虹膜认证（[BBC](https://www.bbc.com/news/articles/cp9vppem4evo)）；国内蓝 V/真人认证标识被普遍当作曝光与匹配效率的代理指标（[知乎分析](https://zhuanlan.zhihu.com/p/136165938)）。

**法律边界（事实，《互联网信息服务算法推荐管理规定》）**：公示算法相关规则（第 7 条）；不得把违法信息记入用户标签（第 10 条）；**提供不针对个人特征的选项或便捷关闭入口 + 用户标签可查看/删除**（第 17 条）；显著位置标注备案号（第 26 条）；违反可处警告至 10 万元罚款（第 31 条）（[全文](https://www.cac.gov.cn/2022-01/04/c_1642894606364259.htm)）。

**推断的产品规则（三条，缺一不可）**
1. **权重与付费物理隔离**：
   - Boost = 付费、限时置顶、**明确不参与契合度公式**（现有代码里 Boost 只弹 toast：`⚡ Boost 已开启：未来 30 分钟优先展示`，见 [src/i18n.tsx:133](file:///d:/Agent/Roommix/src/i18n.tsx#L133) → 真实现时要做成"排序插入"，不改分数）。
   - 认证加权 = 免费、一次性、**可解释**：文案写成"你完成学历核验，7 天内展示权重 +X%"，而不是"给你更多喜欢"。
2. **必须有"关闭个性化推荐"入口**；关闭后仍保留基于 10 题答案的契合度排序（这就是"不针对个人特征的选项"）。
3. **算法规则公示 + 备案号展示**：落地为一个"我们怎么排序"的公开页（同时可作为路演时的信任道具）。

> 上架侧提醒（事实）：应用商店要求隐私政策弹窗先行、不得未同意即采集（[华为审核指南](https://developer.huawei.com/consumer/cn/doc/50104)、[小米隐私合规标准](https://dev.mi.com/distribute/doc/details?pId=1325)）；工信部 **App 备案自 2023-09 施行**，未备案不得提供接入/分发（[通知](https://www.secrss.com/articles/57561)、[央视网](https://news.cctv.com/2023-08-09/ARTInvBUGPSDI35aK6WoSMYW230809.shtml)）；经营性互联网信息服务另需增值电信业务许可（[工信部平台](https://tsm.miit.gov.cn/dxxzsp/)）。

## 6. MVP 排序建议（实现成本 × 信任收益）

### T0 · 上线前演示必须做（6 项，全部不依赖企业级商务谈判）
1. **手机号 + 身份证二要素实名**——法规底线，云 API 几分/次。
2. **真人认证 v1**——走**供应商合规 SDK**（阿里云/腾讯云实人认证，只拿"通过/不通过"回调），**不自建云端人脸比对**（受《人脸识别技术应用安全管理办法》"人脸信息不得经互联网外传"约束，见 3.5）；必须同时提供**非人脸替代路径**（邮箱验证码 / 学信验证码 / 人工抽审）。通过后蓝 V + "核验方式"说明页 + 单独同意弹窗。
3. **年龄门槛**——18 岁生日自填 + 身份证一致性校验；演示阶段就能展示，直接回应未成年人红线。
4. **性别偏好三档筛选**——"不限 / 只看同性 / 优先女生（或男生）"，只影响排序不影响可用性；女性默认位置脱敏到行政区。
5. **UGC 先审后发接机审**——成本 0.05–0.065 元/百张，几乎可忽略。
6. **认证加权的最小可解释版本**——"认证用户优先展示 7 天"开关 + "关闭个性化推荐"入口 + "我们怎么排序"公示页。

**演示时的讲法（推断）**：把 T0 的 1/2/3/6 做成一条 90 秒的"信任流程"（登录 → 自拍核验 → 徽章出现 → 卡片出现"已实名·真人已核验"），比任何一页 PPT 都更能回答"对面是骗子怎么办"。

### T1 · 上线后 3 个月内
7. **学历核验**（学信在线验证码，零 API 成本，信任收益极高）。
8. **工作核验 v1**（企业邮箱域名白名单验证码，覆盖腾讯/字节等大厂；工牌 OCR + 人工抽审兜底无邮箱岗位）。
9. **隐私粒度控制**：公开公司名 / 仅公开城市二选一，复用 Soul"仅获取认证结果"的表述模式。
10. **房源侧身份核验与房源发布码对接**（先按第 5 节的"仅分享不发布"推迟义务）。
11. **算法备案 + App 备案 + ICP/增值许可**——周期最长，越早启动越好（备案 30 个工作日、人脸/小程序资质审核 3–5 个工作日）。

### T2 · 远期
12. **权威库实人核身**（1–1.5 元/次，且小程序形态受行业资质限制，社交场景性价比最低）。
13. **网号/网证接入**（自愿、企业侧免费，但需改造身份系统并等公共服务开放节奏）。
14. **第三方背调式深度认证**、付费 Boost 与认证加权完全隔离的产品化（先做"认证换免费曝光券"，参照 Tinder 5 次 Boost 模型）。

## 7. 一句话总结

**大陆版真正的差异化不是"找室友"这个玩法，而是"把信任做成可见的产品层"**：性别偏好（安全）、四类徽章（身份）、可解释的曝光加权（激励）、房源核验（合规）。而这四项里，**三项是法规必做**——把它们做成演示里最亮的部分，而不是成本中心。
