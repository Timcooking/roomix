# Roomix PPT 设计输入

## 使用边界

这份材料用于支持另一位 Agent 独立设计 PPT。页数、叙事顺序、视觉与版式均可自行决定，不必沿用现有 HTML 或废稿 PPT。

必须保持三条事实边界：

- 香港版本是当前可体验的静态前端 Demo；中国大陆功能属于上线前规划，不能写成已经上线。
- 100 份问卷与 5 位深访均为合成样本，只能标注为“模拟调研”，不能写成真实回收或真实访谈。
- 市场规模、租金、服务费、政策与认证能力应保留下文口径，不要把测算或产品假设写成确定事实。

## 1. 产品是什么

Roomix 是一个先匹配室友、再由两个人共同选择房源的合租产品。

当前香港 Demo 的核心链路：

1. 用户回答 10 道生活习惯问题。
2. 生成个人卡片与契合度。
3. 滑动选择室友，双方喜欢后完成配对。
4. 配对的两个人进入共享房源卡组。
5. 双方都喜欢同一套房后，进入预约看房。

一句话产品逻辑：**先滑到一个室友，再一起滑到一间房。**

当前全球版底部导航为：`室友 / 房源 / 消息 / 我的`。

## 2. 产品设计理念

### 人先于房

传统租房产品先展示房源，Roomix 先帮助用户判断“能否共同生活”。房源是两个人生活预期的下一步，而不是唯一入口。

### 双向决策

不仅室友匹配需要双方喜欢，房源也需要双方共同喜欢。产品重点不是增加单人刷房次数，而是帮助两个人完成共同决策。

### 可解释的契合度

契合度来自作息、整洁、吸烟、预算、宠物、区域等生活问题。分数应当能回到具体生活习惯，而不是不可解释的黑箱。

当前 Demo 使用加权规则：相同记 1、接近记 0.55、不同记 0，归一化后映射到 52–98 分。作息与整洁权重较高。

### 轻交互，不轻率

滑动降低了表达偏好的成本，但合租仍是高信任决策。认证、隐私、房源核验和看房安排需要补足滑动背后的信任基础。

### 信任可见，隐私可控

认证结果可以以徽章呈现，不代表必须公开完整公司或学校。用户可以选择仅显示徽章、显示城市或园区、显示完整单位。

### 全球体验与本地信任层分离

大陆本地化不应推翻已经跑通的“测评—匹配—共同刷房—看房”链路，而是在同一链路上增加身份、房源、隐私与合规能力。

## 3. 当前产品基线

技术状态：Vite + React 19 + Motion 的纯静态前端，无后端、账号体系或数据库。

已有能力：

- 简中、繁中、英文界面。
- 10 题生活习惯测评与个人卡片。
- 契合度分数与生活习惯对照。
- 室友卡片滑动、撤回、超级喜欢等演示交互。
- 双向配对演示。
- 配对后的共享房源卡组与共同喜欢演示。
- 房源详情、消息与个人页面。

仍是占位或演示脚本的能力：

- 筛选、通知、Boost 等部分操作主要显示 toast。
- 对方喜欢、共享房源推进等由演示脚本驱动。
- 没有真实账号、认证、数据库、支付或预约后端。
- 当前 `Person` 数据没有性别字段，只有一个演示用 `verified` 标记。

## 4. 中国大陆与全球版对比

| 维度 | 全球版 / 香港 Demo | 中国大陆规划 |
| --- | --- | --- |
| 核心链路 | 测评、匹配、共同刷房、看房 | 保留同一链路 |
| 室友偏好 | 暂无性别字段与性别筛选 | 同性、异性、随机，默认随机 |
| 实名 | 演示用 verified 标记 | 接入合规身份核验，核验发布者身份 |
| 真人认证 | 无 | 优先供应商 SDK 返回结果，并提供非人脸替代路径 |
| 职业认证 | 无 | 用户授权材料核验，显示职业徽章 |
| 学历认证 | 无 | 用户提交学信网在线验证码或报告，平台核验 |
| 公司 / 学校公开 | 资料按 Demo 展示 | 仅徽章、城市 / 园区、完整单位，由用户选择 |
| 房源信任 | 演示房源与共享卡组 | 发布者身份核验、房源核验、虚假房源治理 |
| 推荐与曝光 | Boost 等为占位交互 | 规则公示、算法备案评估、关闭个性化推荐入口 |
| 租金押金 | 无交易能力 | 平台不代收代付租金与押金 |
| 底部导航 | 室友 / 房源 / 消息 / 我的 | 保持四标签，替换信任与隐私能力 |
| 产品状态 | 可体验静态 Demo | 上线前规划，需要后端与合规建设 |

补充判断：

- 学信网没有面向企业的通用商用 API，不应写成“直接调用学信网接口”。
- 人脸识别不应默认采用自建云端自拍比对；需要供应商合规能力与非人脸替代路径。
- “认证后增加曝光”不是必须保留的默认方案，需要同时评估用户接受度、算法推荐公示与关闭入口。

## 5. 用户与市场证据

### 市场背景

- 全国租房人口近 **2.6 亿**。
- 四大一线城市租房人口近 **4000 万**。
- 2026 届高校毕业生预计 **1270 万人**。
- 《中国青年租住报告》的泊寓客户面板显示：平均年龄从 27.2 岁升至 29.7 岁，平均决策周期从 9.9 天升至 18.8 天，续租率从 47.4% 升至 63.4%。该数据来自单一品牌约 150 万在租客户，外推需谨慎。
- 《住房租赁条例》于 2025-09-15 施行，强化房源信息发布者身份核验等责任。
- 《人脸识别技术应用安全管理办法》于 2025-06-01 施行。

### 模拟调研方法

- 15 题问卷，包含开放题。
- 100 份合成样本，固定随机种子生成。
- 5 位合成深访人物，用于提炼需求与画像。
- 城市：上海 25、深圳 25、杭州 20、北京 15、成都 15。
- 年龄：22–25 岁 39%、26–29 岁 30%、30–35 岁 31%。

完整统计见 `data/research-stats.json`。

### 关键发现

- 虚假房源与生活习惯不合均为 **62%**，并列首要痛点。
- 身份不实与押金费用不透明均为 **53%**。
- **80%** 对契合度给出正向评价。
- **75%** 对共同刷房给出正向评价。
- 最能提升信任的认证：实名 **82%**、房源 **81%**、真人 **63%**、职业 **62%**、学历 **47%**。
- **77%** 选择有限公开：仅徽章 51%、城市或园区 26%；完整公开单位或学校仅 14%。
- 人脸认证：愿意 33%、需要说明和替代路径 43%、不愿意 24%。
- 付费：仅接受免费 40%；只为押金、签约等保障服务付费 7%。

### 三个合成画像

**林悦，25 岁，上海，品牌运营**

- 预算约 ¥4,500，重视通勤、安静与整洁。
- 先判断生活方式，再决定是否共同看房。

**陈昊，28 岁，深圳，产品经理**

- 重视实名与职业徽章。
- 接受认证，但不愿默认公开完整公司。

**周雨桐，23 岁，杭州，应届硕士**

## 6. 竞品结论

### 直接竞品

- Roomi、CoHabby、ideal flatmate、Diggz、RoomSync 等已经提供室友匹配、问卷或兼容性机制。
- 因此不能宣称 Roomix 是“全球首创室友契合度算法”。

### 间接竞品

- 贝壳、自如等强在房源、交易与运营。
- 豆瓣、小红书、微信群、闲鱼等强在信息分发与用户自发连接，但身份、共同决策和流程治理较弱。
- Wellcee 等产品兼有社区与找房属性。

### 可防守的差异化

Roomix 的差异化不应只落在“有契合度算法”，而应落在：

**可解释的生活契合度 + 双向室友匹配 + 双人共同房源决策。**

## 7. 大陆版功能结构

### 室友

- 生活习惯测评。
- 性别及其他偏好筛选。
- 契合度与习惯对照。
- 双向匹配。

### 房源

- 配对后的共享房源卡组。
- 发布者与房源核验。
- 双方共同喜欢。
- 预约看房。

### 消息

- 配对会话。
- 看房安排。
- 系统通知。

### 我的

- 实名、真人、职业、学历徽章。
- 公司、学校与公开粒度管理。
- 推荐与隐私设置。

## 8. 实施优先级

### P0：信任链路

- 性别偏好。
- 实名核验。
- 房源发布者与房源核验。
- 非人脸替代路径。
- 平台不经手租金与押金。

### P1：职业、学历与隐私

- 职业与学历认证。
- 徽章与公开粒度。
- 推荐规则公示。
- 关闭个性化推荐入口。

### P2：共同决策与服务

- 共同刷房、共同喜欢、看房转化数据。
- 签约或押金保障服务。
- 城市扩展。

## 9. 商业模式与衡量指标

原香港路演提出过“租金 2%、最多 6 个月”的服务费假设。该数字只能标注为待验证假设；进入中国大陆前需要重新评估合规、支付路径与用户接受度，平台不经手租金押金。

建议的北极星指标：

**共同喜欢同一套房并完成看房。**

配套指标：

- 配对到共同刷房的转化率。
- 共同喜欢到看房的转化率。
- 有效看房率。
- 虚假信息与举报率。
